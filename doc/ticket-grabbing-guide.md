## 1. 前置要求

### 1.1 硬件
- **安卓手机**（推荐）或安卓模拟器（NoxPlayer / MuMu / 雷电）
- Android 版本：建议 10+
- RAM：4GB+
- 屏幕分辨率：**1080×2340 或更高**（脚本默认坐标基于主流分辨率）

### 1.2 软件
| 软件 | 版本 | 说明 |
|---|---|---|
| AutoX.js | **6.5.8** | 作者指定版本，别用最新 beta |
| 猫眼 APP / 纷玩岛 APP / 票星球 APP | 最新稳定版 | 从官方应用商店装 |
| Android 系统 | 10+ | 低版本无障碍 API 不全 |
| ADB（可选） | 最新 | 连 PC 调试脚本用 |

### 1.3 账号
- 目标 APP 已登录**实名**账号
- **已添加观演人**（猫眼/纷玩岛/票星球在"我的-观演人"里加身份证信息）
- **已开启免密支付**（支付宝或微信，省 3-5 秒）

## 2. 环境搭建（首次运行必做）

### 2.1 安装 AutoX.js 6.5.8

```
① 打开浏览器访问: https://github.com/kkevsekk1/AutoX/releases
② 找到 v6.5.8（或 Pactum7 作者最后测试通过的版本）
③ 下载 autox.js-xxx-v6.5.8-release.apk 到手机
④ 安装（需允许"未知来源应用"）
```

### 2.2 授予 AutoX.js 权限（**缺一个都跑不了**）

打开 AutoX.js → 点右上角三个点 → 设置 → 权限设置：

| 权限 | 作用 | 必须 |
|---|---|---|
| **无障碍服务** | 读取 APP 控件、模拟点击 | ✅ 必需 |
| **悬浮窗** | 日志提示、停止按钮 | ✅ 必需 |
| **通知** | webhook 外不想错过 | ✅ 必需 |
| **电池优化** | 关闭对 AutoX.js 的电池优化 | ✅ 必需 |
| **存储权限** | 读取脚本文件 | ✅ 必需 |
| **自启动** | 防止被系统杀后台 | ✅ 必需 |

**关键**：进入 系统设置 → 无障碍 → 将 AutoX.js 打开；若失效，**重启手机**再开一次。

### 2.3 下载脚本到手机

**方法 A：手机端 Git（推荐）**
```
① 在手机安装 Termux（GitHub 上的 Termux 更新版）
② pkg install git
③ cd /sdcard
④ git clone https://github.com/Pactum7/ticket-grabbing
⑤ 打开 AutoX.js，"选择目录"指向 /sdcard/ticket-grabbing
```

**方法 B：电脑下载后传输**
```
① PC git clone https://github.com/Pactum7/ticket-grabbing
② 用 QQ/微信/USB 把整个目录传到手机 /sdcard/Scripts/
③ AutoX.js 里打开这个目录
```

**方法 C：AutoX.js Web IDE（最方便）**
```
① AutoX.js 首页 → 右下角 + → 开启"连接电脑"
② 会显示一个 IP:端口，如 192.168.1.10:9317
③ PC 浏览器打开这个 IP，进入 Web IDE
④ PC 把脚本拖进 Web IDE，自动同步到手机
```

### 2.4 跑通测试脚本

```
① AutoX.js → 打开 /Test/Test.js
② 点右下角"运行"▶
③ 应弹出 toast 提示或简单交互
④ 如失败 → 检查无障碍权限、悬浮窗权限
```

## 3. 开售前 24 小时：配置演练

### 3.1 场景：猫眼 · 某场演唱会 2026-05-18 20:00 开售

#### Step 1 打开猫眼 APP
- 搜索目标演出 → 点进详情页
- **提前预约**（"立即预约"按钮）
- **预填观演人信息**（避免开售时还要填）
- 停在演出详情页，不要退出

#### Step 2 配置 MaoYanGoNew.js

用 AutoX.js 打开 `MaoYan/MaoYanGoNew.js`，编辑头部：

```
// 核心配置（根据你手机实际分辨率调整）
var ConfirmX = 878;          // "立即购买"或"确认"按钮 X 坐标
var ConfirmY = 2263;         // Y 坐标
var isDebug  = false;        // 正式抢票关闭调试
var debugTicketClickX = 207; // 调试模式下的票档点击 X
var debugTicketClickY = 1170;// 调试模式下的票档点击 Y
```

**怎么确定 ConfirmX/Y**？
```
① 打开猫眼，进到一个"有票"的页面（任意一个可购演出）
② 肉眼观察"立即购买"按钮在屏幕的位置
③ 用 AutoX.js → 悬浮窗 → 查看布局：点击按钮可看到坐标
④ 把坐标填进 ConfirmX/Y
⑤ 不同分辨率手机，坐标不同，每台机都要校准
```

#### Step 3 流程自检（用 isDebug=true 跑一次）
```
① 改 isDebug = true
② 脚本会在"调试票档"坐标(207,1170)模拟点击
③ 观察脚本能否：
    - 找到"立即预订"按钮
    - 自动点"确认"
    - 跳转到支付页
④ 走通后，改 isDebug = false，保存脚本
```

#### Step 4 配置 MaoYanMonitor.js（回流监控）

```
var monitorIntervalSeconds = 2;                    // 2 秒刷一次
var webHookNoticeUrl       = "";                   // 填 Bark 或企业微信 URL
var isRingingBell          = true;                 // 响铃提醒
var isDebug                = false;
var defaultPlayEtcStr      = "05-18,05-19";        // 想要的场次日期，逗号分隔
var defaultMaxTicketPrice  = 800;                  // 最高愿意接受的票价
var defaultViewers         = "观演人a,观演人b";    // 观演人姓名，和 APP 里保持一致
```

**Webhook 通知接入 Bark（iOS）**：
```
① App Store 下载 Bark，获取推送 URL（形如 https://api.day.app/xxxxx/）
② webHookNoticeUrl = "https://api.day.app/xxxxx/"
③ 脚本监测到有票时会推送到 iPhone，声音+震动
```

**Webhook 通知接入企业微信机器人**：
```
① 企业微信群 → 添加机器人 → 拷贝 webhook URL
② webHookNoticeUrl = "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"
```

## 4. 开售前 1 小时：联调清单

```
□ 手机剩余电量 > 50%，或插着电源
□ 关闭其他后台 APP，只留目标 APP + AutoX.js
□ 关闭"勿扰模式"，确保能响铃
□ Wi-Fi 或 5G 信号满格（建议 5G + 家宽二选一）
□ 系统时间已"自动同步"
□ 目标 APP 已登录，停在演出详情页
□ 观演人、免密支付都配置完毕
□ AutoX.js 无障碍权限还亮着（系统更新常自动关闭）
□ 脚本 isDebug = false
□ webhook 发了一条测试消息，确认能收到
```

**关键**：AutoX.js 无障碍权限被系统 "杀"是最常见事故。**每次开售前 10 分钟，重新开关一次无障碍开关** 确保激活。

## 5. 开售瞬间：T-0 执行流程

### 5.1 猫眼（卡点型）：T-30s ~ T+60s
```
T-2min:  打开猫眼到目标演出详情页
T-30s:   AutoX.js → 打开 MaoYanGoNew.js → 点运行
         脚本会自动：
            ① 循环刷新页面
            ② 等待"立即预订/立即购票"按钮出现
            ③ 自动点击 → 跳到订单页
            ④ 连点"确认"按钮到支付页
T+0:     你手指也同时停在"立即购买"上配合
T+3s:    脚本若成功，跳到支付页，手动或免密完成支付
T+15s:   没抢到？保留页面，启动 Monitor 转入回流
T+60s:   完全没票？切换 Monitor 脚本
```

### 5.2 纷玩岛（定时型）：
```
T-5min:  AutoX.js → 运行 FenWanDaoGo.js
         弹窗输入 "05-18 20:00"
         脚本开始轮询大麦服务器时间
T-0:     脚本自动点击"立即预订"
T+2s:    自动完成"确认→提交订单"
T+5s:    进入支付页 → 手动/免密支付
```

### 5.3 手动兜底
**不要纯靠脚本**。手指应停在"立即购买"按钮上，和脚本同时抢。谁先进订单页就谁付钱。

## 6. 开售后：回流监控（命中率 > 开售瞬间）

### 6.1 启动 MaoYanMonitor.js

```
① 打开猫眼，搜索目标演出，进入票档选择页（显示各价位的那个页面）
② ⚠️ 必须停在这个页面，不是详情页
③ AutoX.js → 打开 MaoYanMonitor.js
④ 点运行，按提示输入：
     - 场次日期（如 "05-18"）
     - 最高票价（如 800）
     - 观演人（如 "观演人a"）
⑤ 脚本开始双线程工作：
     线程 1：每 2 秒点一次"刷新场次"
     线程 2：扫描是否出现 ≤ 800 元的票档
⑥ 检测到可买 → 自动点击 → 选观演人 → 提交订单 → Webhook 通知 + 响铃
```

### 6.2 关键时间窗口（命中率递增）
| 窗口 | 说明 | 建议动作 |
|---|---|---|
| **T+10min** | 开售后未付款订单回退，**命中率最高** | Monitor 必开 |
| **T+20~30min** | 二次回退高峰 | 继续开 |
| **T+24h** | 第一波冷静期退款 | 挂机 24h |
| **T+72h** | 最后退款回流潮 | 继续挂 |
| **演出前 7 天** | 强制实名认证前退票 | 重点关注 |
| **演出前 24h** | 急售/加场 | 最后机会 |

### 6.3 长期挂机技巧
```
① 手机插电源
② 关闭屏幕自动锁（或设置为 10 分钟）
③ 开启 AutoX.js 的"保持屏幕常亮"
④ 关闭系统级省电模式
⑤ 给 AutoX.js 打开"后台运行"白名单
⑥ webhook 通知开启，不用一直看手机
```

## 7. 报错排查表

### 7.1 脚本启动无反应
| 症状 | 原因 | 处理 |
|---|---|---|
| 弹出"请主动点击中间票档区域缺货登记刷新 dom" | APP 的票档页面控件未激活 | **手动点一下"缺货登记"按钮，再关闭弹窗**，脚本即可识别 |
| 完全无日志 | 无障碍被关闭 | 设置 → 无障碍 → AutoX.js 重新打开 |
| 提示"找不到控件" | APP 版本改版 | 降级 APP 版本或等脚本更新 |

### 7.2 点击位置错乱
| 症状 | 原因 | 处理 |
|---|---|---|
| 点到别的按钮 | ConfirmX/Y 和你的分辨率不匹配 | 用 AutoX.js 布局分析器重新取坐标 |
| 调试模式点不中票档 | debugTicketClickX/Y 错 | 同上 |

### 7.3 时间校准
| 症状 | 原因 | 处理 |
|---|---|---|
| 脚本在开售前提前点了 | 本地时间快 | 系统设置打开"自动同步时间" |
| 脚本总是慢 1 秒 | 网络延迟大 | 切 5G，或改用纷玩岛脚本（它拉服务器时间） |

### 7.4 AutoX.js 崩溃
| 症状 | 处理 |
|---|---|
| 运行中闪退 | 降版本到 **6.5.8** |
| 启动时卡白屏 | 清 AutoX.js 数据后重新授权 |
| 内存不足 | 关闭其他所有 APP，只留目标 APP + AutoX.js |

### 7.5 付款阶段卡住
脚本不负责自动付款（免密除外），**自己在订单倒计时内完成**：
- 猫眼：默认 15 分钟
- 纷玩岛：默认 10 分钟
- 超时订单作废，**不会自动补票**

## 8. 避坑清单

### 8.1 必做 ✅
- [ ] 用 **AutoX.js 6.5.8**，别用最新版
- [ ] 每次抢票前 10 分钟**重开无障碍开关**
- [ ] 观演人姓名和 APP 里**完全一致**（空格、全角半角都要对）
- [ ] isDebug 正式抢票**必须关闭**
- [ ] 分辨率坐标**每台手机单独校准**
- [ ] 运行前先跑 Test.js 确认环境
- [ ] Webhook 做通知兜底

### 8.2 禁忌 ❌
- ❌ 用他人身份证账号（实名不一致进不去场）
- ❌ 一个账号多端同时抢（会互踢登录）
- ❌ 开抢前 5 分钟才打开 APP（登录态可能已失效）
- ❌ 多次连点（脚本已做节奏，乱点反而触发风控）
- ❌ 订单页停太久才付（超时作废）
- ❌ 关机/锁屏（脚本不会运行）

### 8.3 关键现实预期
- 热门场次脚本命中率 **< 20%**，甚至 < 10%
- **回流监控命中率反而比开售瞬间高**（因为很多人不付款）
- 纷玩岛因抢票周期长，**脚本相对优势最大**
- 脚本**不会帮你抢到原本抢不到的票**，只是提高手速上限

## 10. 进阶：ticket-notice（Java 通知后端）

仓库里的 `ticket-notice/` 是个 Java Spring Boot 项目，提供统一的 webhook 接收端，可部署到服务器后转发到多个通知渠道（Bark / 企业微信 / 钉钉 / 邮件）。

**使用场景**：
- 有服务器、想做统一通知中心
- 多场演出同时监控，通知内容分类
- 对接家人手机的 Bark 一起提醒

**部署**：
```
cd ticket-notice
mvn clean package
java -jar target/ticket-notice-xx.jar --server.port=8080
# 脚本 webHookNoticeUrl 填 http://your-server:8080/notice
```

**非必需**：个人用户直接用 Bark 官方 URL 最省事。
